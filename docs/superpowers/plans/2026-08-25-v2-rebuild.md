# RainHue v2 Rebuild — Implementation Plan

**Goal:** Rebuild with remote Hue OAuth API, locked color logic (precip primary), morning CLI + small HTTP API, env config, full pytest coverage.

**Architecture:** clean modules — `config.py` (env), `weather.py` (Open-Meteo fetch → typed Forecast), `colors.py` (pure decision function), `hue.py` (remote CLIP v2 client + OAuth refresh), `core.py` (run-one-cycle orchestration), `cli.py` (`python -m rain_hue morning`), `api.py` (Flask, POST /set-color, GET /weather).

**Locked color logic:** precip in next 12h beats temperature. Rain → blue, deeper/more saturated with intensity. Snow → cold white, brighter with intensity. No precip: >30°C red, >25°C orange, else neutral warm-white. All thresholds env-configurable.

**Decisions (minimal, noted):**
- Hue remote CLIP v2 API (`api.meethue.com/v2/clip/v2/resource/light`) with `color.xy` + `dimming.brightness`.
- Token refresh: POST oauth2/token (client basic auth); new tokens printed to stdout for manual .env update (CLI is stateless; refresh tokens rotate). If HUE_CLIENT_ID/SECRET unset and token expired → clear error.
- Colors as [xy, brightness, gamut] presets derived per intensity band.

**Tasks:**
1. config.py — env loader with threshold defaults
2. weather.py — fetch + parse (hourly precip prob/amount/snowfall, daily max temp) → Forecast dataclass; raises on failure
3. colors.py — decide_color(forecast, thresholds) → ColorDecision (pure, exhaustive tests)
4. hue.py — HueClient: ensure_token (refresh on expiry), find light by name, set state
5. core.py — run_once(lamp override) → decision + apply; shared by CLI & API
6. cli.py — argparse `morning` (one run), `--lamp` override
7. api.py — Flask factory; POST /set-color (?lamp=), GET /weather
8. tests — colors exhaustive; weather parse mocked; hue client mocked (refresh + set); api routes mocked; cli end-to-end mocked
9. .env.example, createconfig.py (adds OAuth vars), README v2, requirements (drop phue)
